# 研究任务范围与引用快照

研究任务不再复制整库成员，也不再校验整个集合是否与创建任务时一致。

| 来源 | 保存内容 | 检索方式 |
| --- | --- | --- |
| 全库 | 会话不绑定知识库或根数据库 | 不添加库成员限制；候选按当前文献权限和索引状态核验 |
| 知识库 | 会话的 `knowledge_base_id` | 根据当前 `knowledge_base_document` 关联查询 |
| 根数据库 | 会话的 `database_id` | 根据当前有效分类子树及文献关联查询 |
| 明确选文 | `research_run.request_payload.corpus_ids`，保留顺序 | 在明确选文内校验当前权限和索引状态 |
| AI 知识库写作 | `request_payload.writing.knowledge_base_id` | 根据该知识库当前成员检索，不扩大到全库 |

## 执行规则

- 创建全库任务不枚举文献 ID、不读取完整题录、不批量写入范围关联。
- 普通全库正文检索直接进行向量和词法召回，仅回查命中候选的元数据、权限及当前索引构建。
- 资源查询及明确选文仍在实际检索时检查权限、审核状态、附件摘要和双路索引就绪状态。
- 成员新增、移出和题录变动不会使整个任务失效；检索时已失效的候选被排除。
- AI 查文献翻页复用已保存的搜索条件，查询当前范围，因此数据变化后总数和分页内容允许变化。
- 阅读追问保留原卡片指向的篇目，读取当前可读材料；材料版本变化后不复用旧版分析。

## 已取得的证据

生成及发布使用本轮受控检索已经取得的证据。`research_evidence` 保留原文、页码、文件路径、
片段定位及内容哈希，`research_citation` 保留实际采用的引用摘录。发布前不重新扫描成员或比较
当前附件；文献后来删除、附件更新或权限撤销，不追溯取消已经取得证据的本轮回答。

引用仍必须属于本轮检索，摘录必须来自真实证据，已保存证据的来源及内容哈希必须一致。
原文文件读取接口继续按请求时的权限和文献状态处理，历史引用的原文可能已经不可用。

## 文献阅读推荐

文献阅读的联网文献推荐暂时关闭，不发起模型联网搜索，也不执行联网候选的全库去重。
库内推荐和基于所选文献的模型分析、继续提问照常运行。联网分路记录 `SKIPPED/DISABLED`，
不会把主动停用视为失败；仅库内推荐阶段的节点等待上限为 30 秒。

后续需要恢复时，将 `literature_graph.py` 中的 `ENABLE_WEB_RECOMMENDATIONS` 改为 `True`。

## 文献问答输出语言

独立文献阅读及 AI 入口的文献阅读统一生成中文：逐篇分析、综合概览、创新方向、分项标签、
推荐问题和继续提问均采用简体中文。外文原文、外语问题或要求切换语言不改变此规则。
每次模型调用都会补齐中文要求，因此历史任务保存的旧 Prompt 也受到相同约束。

新生成内容出现没有中文说明的外语段落时，分析最多纠正一次；追问和指代规划沿用已有的
重试预算，不叠加更多轮次。正常中文结果不增加模型调用。运行记录输出语言固定为 `ZH`。
此检查只作用于新生成内容，不重写历史答案，也不改动题录原题、作者及真实引用原文。
初次分析的去重标识包含当前中文生成约束，重新发起分析不会复用旧版外语分析结果。

## 部署及历史兼容

- 在各自 Backend 目录拉取对应分支：生产 master 执行 `sh deploy.sh`，测试 dev 执行
  `sh deploy-dev.sh`，更新相应 Research Agent。两套服务继续使用各自的端口和索引配置。
- `research_run_corpus` 已退出业务读写、迁移创建和启动就绪检查。现存旧表和数据不自动删除，
  避免部署过程进行无必要的数据清理；新部署无需此表。
- 旧任务按原会话资源绑定或请求中的明确选文恢复，不依赖旧表。历史消息、证据、引用不重写。
- `research_run.scope_version` 为协议兼容保留；新任务使用正整数常量 `1`，不表示集合版本。
- 不需要重建 Qdrant、OpenSearch，也不改变 dev/master 的端口、索引名或 Worker 配置。

离线回归包含六万八千篇全库提交、旧表缺失时任务恢复与翻页、候选权限隔离、资源成员变动、
附件更新和删除后的快照发布，以及原有研究、阅读、写作业务测试。
